# S4.2 + S4.4 - Worker autoscaling, connection pooling, read-replica readiness

Date: 2026-06-12. Slices: backlog 0001 S4.2 (Celery worker and queue autoscaling; idempotent
high-volume ingestion) and S4.4 (PostGIS read replicas and connection pooling), PRD 0001
R15/R18. Status: DONE for everything runnable on the existing deployment; the one piece that
needs new infrastructure (provisioning an actual streaming replica) is built behind a config
switch and flagged ⚑ CONFIRM.

## Scope decision

These two slices are "deployment-shaped": their full form (a replica host, an orchestrator
scaling worker replicas) only exists once there is a production deployment. The runnable core
was shipped now so that deployment day is a config change, not a code change:

- Everything mechanical is env-driven (pool sizes, autoscale bounds, the replica DSN).
- The read/write session split is wired through the endpoints today, with the read engine
  falling back to the primary engine object itself when no replica is configured, so the
  default deployment pays nothing for the indirection.
- S4.2's "idempotent high-volume ingestion" half was already proven by the S4.7 load test
  (89.5 rps on the idempotent replay path) and the existing enqueue-time dedup/locking (R-1).

## What shipped

**S4.2 - worker scaling.**

- The compose worker runs `--autoscale=${RS_WORKER_AUTOSCALE:-4,1}` (max,min - compose
  interpolates it from `.env`; the app itself never reads it). Verified live: the boot banner
  shows `concurrency: {min=1, max=4} (prefork)`.
- `worker_prefetch_multiplier=1` in the Celery config: collection tasks run seconds to
  minutes, so a process must never hoard a prefetch window of them while siblings idle; one
  reserved task per process pairs with the existing `task_acks_late` for fair dispatch and
  clean redelivery when a worker dies.
- Horizontal scale-out is `docker compose up -d --scale worker=N`. This was already safe:
  enqueue-time dedup/locking keeps concurrent workers from double-processing a scene, and
  migrations live in the one-shot `migrate` service, not app startup.
- Queue separation (routing collection vs maintenance to distinct queues) was considered and
  deliberately skipped: one queue plus autoscale is sufficient at current volumes, and
  premature routing adds operational surface with no measured need.

**S4.4 - pooling and read routing.**

- Pool tuning is config: `RS_DB_POOL_SIZE`, `RS_DB_MAX_OVERFLOW`, `RS_DB_POOL_TIMEOUT_S`,
  `RS_DB_POOL_RECYCLE_S` (defaults = SQLAlchemy's own), built by the pure
  `rs_core.db.engine_kwargs` and applied to every app engine. `pool_pre_ping` stays
  unconditional.
- `RS_DATABASE_READ_URL` (⚑ CONFIRM, empty default) is the replica switch. The pure
  `read_database_url` decides: empty or equal to the primary means None, and
  `get_read_engine()` then returns the primary engine itself - same object, same pool.
- `get_read_session` is a FastAPI dependency that never commits; `ReadSessionDep` joins
  `SessionDep` in the workspace deps.

**Read-routing decision** (who rides the replica when one exists):

| Read path | Session | Why |
|-----------|---------|-----|
| field timeseries / scenes / as-of / audit, farm fields, farm list | read | Pure analytical reads; staleness = replication lag, harmless |
| `GET /api/v1/mobile/data` (frozen) | read | Results are pushed additively; lag only delays a recovery pull seeing the newest row |
| annotations, interpretations + review queue, publish status | primary | Read-after-write: an analyst writes then immediately reads back |
| collect trigger (`POST /fields/{id}/collect`) | primary | Must always see a just-ingested field |

## The contract gate earned its keep

Extending the `/api/v1/mobile/data` docstring with an S4.4 note failed
`tests/contract/test_openapi_diff.py`: an endpoint docstring IS the frozen route's OpenAPI
`description`, pinned byte-for-byte. The note moved to a code comment and the docstring
reverted exactly. Worth remembering: on frozen routes, docstrings are contract surface, not
documentation.

Likewise, the contract auth tests override `get_session`; once `/data` rode
`get_read_session`, the override had to cover both dependencies (`test_frozen_routes._client`).

## Provisioning the replica (the ⚑ CONFIRM remainder)

When a production deployment exists: provision a PostGIS streaming replica, set
`RS_DATABASE_READ_URL` to it, and size `RS_DB_POOL_SIZE`/`RS_DB_MAX_OVERFLOW` per service
replica count against Postgres `max_connections`. No code change. Revisit the routing table
above if replication lag SLOs make annotation reads safe to move.
