# S2.1 item 1: splitting `rs_core/repositories.py` by aggregate (method + knowledge)

Executed 2026-06-11 on `feat/imagery-agronomy-tiers-0-2`. Commits: `dafaa85` (style debt),
`05e193d` (the split). This doc records the full method, the decisions, and everything learned,
so the remaining S2.1 refactors (items 2 to 4) can replay the recipe instead of rediscovering it.

## What was done

`packages/rs_core/repositories.py` (985 lines, the largest module in the repo) was a flat
god-module of 28 public functions plus 3 private names spanning eight aggregates. It became the
`rs_core.repositories` package, one submodule per aggregate, with `__init__.py` re-exporting
every name so no call site changed:

| Submodule | Contents |
|---|---|
| `scenes.py` | `upsert_scene_metadata` |
| `analyses.py` | `_ANALYSIS_MUTABLE`, `_analysis_upsert_stmt`, `upsert_analysis` |
| `collection_state.py` | `advance_cursor`, `ensure_collection_state`, `get_collection_state`, `record_forward_fill_poll`, `mark_backfill_complete`, `processed_scene_ids` |
| `interpretations.py` | `insert_interpretation`, `get_interpretation`, `get_interpretation_by_id`, `review_interpretation`, `published_narratives_for_farm`, `list_review_queue` |
| `annotations.py` | `insert_annotation`, `list_annotations`, `delete_annotation` |

| `analytics.py` | 4 TypedDicts (`FarmAnalytics*`, `FarmAnomaly`) + `get_farm_analytics_summary` / `_timeseries` / `_anomalies` |

## Pre-flight validation (do this before any split, in this order)

The S2.1 triage classified from signals, not from reading. Before committing to the split, three
facts were established that made it near-zero-risk:

1. **Function inventory.** `Grep '^(async def |def |class )'` over the module gave the real
   skeleton (the first attempt used `^(class |    def ...)` and missed every top-level
   `async def`; pattern carefully). 28 public + 3 private names, mapping cleanly onto 8
   aggregates with no cross-aggregate private helpers.
2. **Blast radius.** `Grep 'repositories'` across the repo (excluding `azure/`): every consumer
   imports via `from rs_core.repositories import <name>`. Only 2 app modules
   (`services/worker/persistence.py`, `services/api/integrations.py`), `packages/rs_core/__init__.py`
   (re-exports 28 names), and 11 test files. A package whose `__init__` re-exports everything is
   import-compatible; nothing else needs editing.
3. **Safety net + baseline.** Nearly every aggregate has a DB suite (`test_analysis_db`,
   `test_annotations_db`, `test_collection_state_db`, `test_farm_analytics`,
   `test_interpretation_review_db`, `test_publish_db`, `test_workspace_db`). Baseline captured
   first: **385 passed, 4 skipped** in ~27s. That exact line is the regression target; any
   deviation after the move means a broken re-export or import.

Key gotcha found in step 2: `tests/test_repositories.py` imports the underscore names
`_ANALYSIS_MUTABLE` and `_analysis_upsert_stmt` directly from `rs_core.repositories`. They are
deliberately part of the tested surface (the upsert statement builder is unit-tested with no DB),
so the package `__init__` must re-export them too, and they belong in `__all__` so ruff's F401
does not flag the re-import.

## The method: verbatim line-range slicing, not retyping

Re-typing 985 lines invites silent drift. Instead a one-shot script sliced the original file by
line ranges and wrote the new modules, with the move provably verbatim:

- **Boundary asserts**: every slice's first and last line is asserted against expected text.
- **Gap asserts**: the lines between slices (and nothing else) are asserted blank, so every line
  1..985 is accounted for: header (replaced per-module), slices, separators.
- **`ast.parse`** on each generated module catches syntax errors before anything is written.
- **Name inventory**: the union of top-level def/class/assign names across the new modules is
  asserted equal to the expected 31-name set. A forgotten function cannot slip through.
- Files written with `encoding="utf-8", newline="\n"` (the repo is autocrlf; LF in, CRLF out on
  checkout). The file contains `§` and similar, so UTF-8 must be explicit on read and write.
- Nothing is written until every assert passes.

The full script is in the appendix. It ran from
`C:\Users\PC\AppData\Local\Temp\split_repositories.py` (left in place; this doc is the durable
copy since Windows clears Temp).

Execution note: the script was first attempted as a `python - <<'PY'` heredoc through the Bash
tool and died with a shell quoting error ("unexpected EOF while looking for matching quote") at
~150 lines. For anything beyond a screenful, write the script to a file and run the file; do not
fight heredoc quoting.

## Decisions worth keeping

- **Re-export, never rewrite call sites.** The package `__init__` carries explicit
  `from rs_core.repositories.<module> import <name>` blocks plus `__all__`. Zero call-site edits,
  zero test edits, `packages/rs_core/__init__.py` untouched.
- **`_ensure_outbox` stays private** to `sync.py`: no test or consumer imports it, so it is not
  re-exported.
- **Inline imports stay inline.** `analytics.py` imports `rs_interpret` *inside* the function
  bodies (3 times), and `collections.defaultdict` once. That is deliberate in the original:
  rs_core must keep no import-time upward dependency on the interpretation layer (same rule that
  keeps rs_core free of rs_imagery / rs_analysis imports). Hoisting them to module level would
  invite an import cycle. The submodule docstring now states this.
- **`git rm` the old file** in the same change. A `repositories.py` module and a `repositories/`
  package can briefly coexist (regular packages win resolution), but never ship that state.
- **Per-module imports are minimal**: each submodule imports only the models and SQLAlchemy bits
  it uses. Ruff verifies both directions (unused and missing).
- **Module docstrings**: the original 17-line module docstring was distributed; each load-bearing
  rule (first-write-wins scene metadata = invariant 2, additive idempotent analysis upsert = D3,
  forward-only cursor = D5) now lives on the submodule that owns it, and the package docstring
  keeps the value-based-boundary rationale.

## Knowledge acquired along the way

- **Ruff isort blank-line nuance**: after an import block, a comment attached to a following
  module-level statement gets exactly **one** blank line, not two. Generating two produced the
  only I001 in the new files; `ruff check --fix` resolved it. (Two blank lines before a bare
  `def`/`class` remain correct.)
- **The branch carried pre-existing ruff debt** (13 errors: import sorting, E501s, an unused
  import) in files from commits predating the frozen rebuild gates: `alembic/versions/0007`,
  `rs_weather/adapters/open_meteo.py`, `worker/collection.py`, two weather tests. Root cause: CI
  (`.github/workflows/ci.yml`) runs `ruff check .` + `ruff format --check .` + full pytest, but
  **only on pushes/PRs to `develop`/`main`**, so a feature branch can accumulate debt silently.
  Run the gates locally per slice; do not rely on CI to catch it on the branch. Fixed in
  `dafaa85` as a separate style commit so the refactor diff stayed a pure move.
- **E501 in string literals**: `ruff format` rewraps code but never strings or docstrings. The
  over-long alembic SQL strings were split with implicit concatenation (byte-identical at
  runtime, keep the space at the seam); the over-long docstring was wrapped across two lines.
- **pytest config**: `testpaths = ["tests"]`, `pythonpath = [".", "packages"]`; `azure/` (the
  robocopy mirror) is ruff-excluded via `extend-exclude` and never collected. Local run skips 4
  tests (live-credential gated); CI runs the DB suites against a service Postgres.
- **Surface check comes free**: importing any `rs_core.*` submodule runs `rs_core/__init__.py`,
  which imports all 28 public names from `rs_core.repositories`. So a single pytest collection
  pass proves the whole re-export surface; no separate smoke script needed.

## Verification (the definition of done for this slice)

- `pytest -q`: **385 passed, 4 skipped**, exactly the pre-refactor baseline.
- New module line counts: `__init__` 89, scenes 49, analyses 111, collection_state 128,

## Replaying this for items 2 to 4

Same recipe for `services/worker/tasks.py` (613 lines, split by task domain),
`services/api/workspace.py` (644, INTERNAL-IMPROVABLE BFF, split routers by resource), and
`services/api/ingestion.py` (466, split validation / mapping / persistence):

1. Grep the real top-level skeleton; map names to groups; confirm no tangled cross-group privates.
2. Grep the import blast radius; decide re-export surface (for FastAPI routers it is the
   `APIRouter` objects and their `include_router` site instead of functions).
3. Run the suite; pin the baseline pass/skip counts.
4. Write a slicing script with boundary asserts, gap asserts, `ast.parse`, and a name-inventory
   assert; only then let it write.
5. `git rm` the old module, `ruff format` then `ruff check`, full pytest; the summary line must
   match the baseline exactly.
6. Commit the pure move alone; put any unrelated lint debt in its own style commit first.

Caveat for item 2: Celery task names. If tasks are registered by dotted path
(`services.worker.tasks.collect_field` style autonaming), moving a task to a new module changes
its registered name and breaks queued/scheduled messages. Check for explicit `name=` on each
`@app.task` (or `task_routes` keys) before moving; pin names explicitly if needed. The workspace
split has no such concern; the contract gate does not freeze the BFF.
