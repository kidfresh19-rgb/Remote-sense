## The judgment call worth recording

**Reading the module revised the triage.** Items 1-3 were genuine god-modules (8 aggregates / 4
task domains / 7 resources jammed flat). Item 4 was not: one cohesive flow, already cleanly
layered internally, with soft triage language to match ("consider splitting"). The honest
options were leave-it-alone or a coarse 3-way cut along seams the code already had. The split
went ahead because the seams coincide exactly with the **test split** (`test_ingestion_logic`
runs validation + matching logic with no DB; `test_ingestion_db` runs persistence + the full
ingest), which makes the boundary real rather than invented. The triage's suggested third
concern, "mapping", was already elsewhere (`integrations.py`), so inventing a module for it
would have been wrong. Rule of thumb extracted: **split along seams the tests already prove,
and stop there.** A 466-line module with one flow does not get the item-1 treatment.
