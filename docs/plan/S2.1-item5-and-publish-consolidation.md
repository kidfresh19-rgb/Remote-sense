# S2.1 item 5 assessment + the publish-endpoint consolidation (notes + knowledge)

Executed 2026-06-11 on `feat/imagery-agronomy-tiers-0-2`. Two pieces of triage follow-through:
the assess-only verdict on the last two flagged modules, and the duplicate-publish-trigger
consolidation that item 3 prepared for.

## Item 5 verdict: keep both modules as-is, no split

- **`rs_core/alerts.py` (327 lines): keep.** Pure threshold evaluation, zero DB. Two clearly
  separated alert families (pipeline health; per-field agronomy), each rule a small pure
  function, an `evaluate_field` composer, three tiny sinks behind a runtime-checkable Protocol.
  The upward-dependency discipline is explicit (takes primitives so rs_core never imports
  rs_analysis / rs_weather). This is a rulebook, not a tangle; splitting would add files without
  removing any complexity.
- **`rs_sync/agritrack.py` (270 lines): keep.** One adapter, exactly as invariant 1 wants it:
  the wire models, the pure payload mapping (`to_satellite_results`, order-stable so a re-push
  is byte-identical), and the resilient transport (`AgriTrackGatewayPort`) in one place. The
  pure-mapping vs transport seam exists but they are two halves of one delivery contract, both
  already unit / contract / parity tested. No action.

Rule reaffirmed from item 4: split along seams the tests already prove, and stop there. Neither
module has such a seam crossing it.

## Publish-endpoint consolidation (behavior slice)

**Decision: the workspace route survives.** `POST /farms/{id}/publish` is what the frontend
calls (`frontend/src/lib/api.ts`), and it is strictly better than the operations duplicate: 404
on an unknown farm, 503 fail-fast on a misconfigured gateway, and a typed `PublishEnqueuedOut`
carrying `gateway` + `dry_run`. The operations `POST /publish/farm/{id}` was a bare enqueue with
none of that; its only callers were three RBAC tests.

Changes:

- `services/api/operations.py`: publish endpoint removed (docstring records where it went);
  the module now carries only `GET /pipeline/health`.
- `tests/test_api_auth.py`: the 403 and 401 publish tests repointed at `/farms/FARM-1/publish`
  (both fire in auth dependencies before any endpoint body, so they stay DB-free). The
  202-enqueue test could NOT be repointed: the workspace endpoint checks farm existence first,
  so a DB-free TestClient call would 404. It moved to `tests/test_workspace_db.py`.
- `tests/test_workspace_db.py`: three new endpoint tests against a seeded farm - the 202 happy
  path (delay patched on the task object, enqueue + subject + shape asserted), 404 unknown farm
  (asserting no enqueue happens), and 503 misconfigured gateway (asserting no enqueue). The
  workspace publish endpoints previously had **no direct tests at all**; the duplicate's removal
  forced the coverage gap closed.
- Docs reconciled: `CONTRACT.md` INTERNAL-OPS section, `workspace/publish.py` docstring,
  `PLAN.md` Phase 7 build-log line (parenthetical note, history kept honest).

### Knowledge worth keeping

- **Test-environment coupling through `get_settings()`**: the workspace publish endpoint reads
  the real env (`gateway_config_error`, `gateway_is_dry_run`), so a test asserting its happy
  path would pass or fail depending on the developer's local `RS_GATEWAY_*` configuration. The
  new tests pin `gateway_config_error` via monkeypatch (green for the 202 test, an error string
  for the 503 test) and assert only the *shape* of `dry_run`, keeping them deterministic on any
  machine. Watch for this pattern whenever an endpoint consults `get_settings()` directly.
- **Removing a duplicate endpoint is also a coverage audit**: the duplicate carried the only
  enqueue test, and the survivor had none. Folding the route without moving + extending the
  tests would have silently dropped the only happy-path coverage of publish-from-the-API.
- The OpenAPI snapshot (`contract/openapi.before.json`) intentionally still lists the removed
  internal route: it is the frozen-contract reference, not a live mirror. The ad-hoc path-set
  parity check from items 3-4 now legitimately differs by exactly this one internal path; the
  real gate (frozen routes only) is unaffected.
