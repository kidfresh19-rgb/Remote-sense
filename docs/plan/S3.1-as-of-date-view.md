# S3.1 as-of-date farm view: the resolution spine (decisions + status)

Executed 2026-06-11 on `feat/imagery-agronomy-tiers-0-2`. The first integrating feature slice of
the rebuild, running on the refactored spine modules and the Phase 1 gate set.

## The settled policy (⚑ CONFIRM)

An arbitrary calendar date resolves to the field's nearest **usable** pass on each side, where
usable means a stored analysis at the field's **current geometry version** whose per-AOI
SCL-derived `clear_fraction` meets `min_clear` (default 0.5, the same floor alerting uses, below
which a pass is not a reliable signal; 0 admits everything). The response carries `before`,
`after`, and `resolved` = the nearer of the two, **tie going to before** because the past is the
safer claim for "as of" semantics. Nothing qualifying means explicit nulls - a pass is never
fabricated (invariant 4), and every returned pass carries its true acquisition date and signed
`day_gap` so the UI labels honestly.

Chosen over nearest-before-only (a request one day before a pass would show a much older view)
and pure bracketing (pushes the choice entirely onto the UI). Both sides still travel in the
response, so the UI offers a one-click flip to the other side - bracketing data, either-side
default. `⚑ CONFIRM` markers sit on `choose_nearer_pass` and its policy test; revisit with the
user.

## What landed

- **L3** `GET /fields/{field_id}/as-of?date=&index=&min_clear=` in `workspace/fields.py`:
  `choose_nearer_pass` (the pure policy), `field_as_of` (two indexed one-row queries, clearest
  scene winning on a multi-pass date, mirroring `field_scenes`' dedup), `ResolvedPass` /
  `AsOfResolution` models, 404 on unknown field. Works identically over backfilled and
  live-collected rows since it reads stored analyses.
- `SceneOut` gained `clear_fraction` (additive), so the pass list shows usability per row.
- **L6** the workspace Scenes panel gained a "Jump to date" control (`AsOfPicker` in
  `SceneList.tsx`): a date input resolves through `useAsOf`, applies the resolved pass to the
  map, and labels it "Showing <true date> · N d before/after · NN% clear", with a one-click
  "use <other date>" flip when the other side exists, and an explicit "no usable pass" message
  when nothing qualifies.
- State model: `requestedDate` in the workspace reducer with a deliberate two-action split -
  `applyResolvedPass` keeps the request (so the label survives), while a manual pass pick via
  scrubber or list (`setPassDate`) retires it, as does any farm/field/view change. This keeps
  the "requested X -> showing Y" context truthful to how the current view was chosen.
- **L5** rendering needed no change: a resolved pass feeds the existing per
  (index, geometry_version, field, scene) tile path, and the index / true-color toggles already
  exist.
