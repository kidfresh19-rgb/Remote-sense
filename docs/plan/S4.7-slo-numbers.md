# S4.7 - Real SLO numbers and the load-test run

Date: 2026-06-12. Slice: backlog 0001 S4.7 (PRD 0001 R12, R15, R16). Status: DONE.

Environment: the dev compose stack (Windows Docker Desktop, one container each of api, tiler,
worker; nginx in front; Postgres 16 + PostGIS, MinIO, Redis), holding real data: 3 farms,
9 analysed fields, 4,290 analysis rows / 858 field-passes of live CDSE `windowed_cog` history
written 2026-06-05 to 06-09. This is the only deployment that exists, so its numbers are the
baseline; re-measure on the eventual production host with the same commands.

Threshold policy: latency thresholds at roughly 2x the measured p95/p99, throughput floors at
roughly half the measured rate. Loose enough to hold across machine variance, tight enough that
a 2x regression fails the gate. The numbers live in `services/loadtest/scenarios.py`; the CLI
exits non-zero on a breach.

## Measured results

| Scenario | Measured | Threshold set |
|----------|----------|---------------|
| tile latency (hot single tile, n=200, conc 10) | p95 177.7 ms, p99 181.5 ms, 0 errors | p95 <= 400 ms, p99 <= 800 ms, 0 errors |
| farm ingest (idempotent replay, n=200, conc 10) | 89.5 rps, p95 213.5 ms, 0 errors | >= 40 rps, p95 <= 500 ms, 0 errors |
| backfill enqueue (worker stopped, n=200, conc 10) | 251.1 rps, 0 errors | >= 100 rps, 0 errors |
| per-field analysis (derived, see below) | worst sustained 35 s/pass effective | p95 <= 60 s |
| pipeline backfill throughput (history) | 1.7-10.2 passes/min/worker sustained | >= 90 passes/hour/worker (operational, doc-level) |

**The R16 data-in proof**: scale is "hundreds of thousands of farms' data in". At the measured
89.5 rps (floor 40 rps) on the idempotent ingest path, 250,000 farm payloads re-ingest in ~47
minutes (under two hours at the floor). Accepting backfill triggers keeps pace at 251 rps. The
data-in edge is not the bottleneck; the CDSE-governed pipeline is, by design (S4.5).

## How each number was obtained (repeatable)

**Tile**: pick a current-geometry analysis row with a COG, compute the z14 slippy tile of the
field centroid, drive it through nginx:

```
SELECT a.index_name, a.geometry_version, a.field_id, a.scene_id,
       ST_X(ST_Centroid(f.boundary)), ST_Y(ST_Centroid(f.boundary))
FROM analysis a JOIN field f ON f.id = a.field_id
WHERE a.cog_uri IS NOT NULL AND a.geometry_version = f.geometry_version
ORDER BY a.created_at DESC LIMIT 1;

python -m services.loadtest --url /tiles/{index}/{gv}/{field}/{scene}/14/{x}/{y}.png \
    --slo-set tile --total 200 --concurrency 10
```

Measured condition is a hot single tile (COG header cached after first reads). The harness
drives one URL per run; a mixed-tile soak needs a URL-list mode, noted as future work.

**Ingest**: export a real farm as its own ingestion payload (psql `json_build_object` +
`ST_AsGeoJSON` over farm + fields), then replay it. Identical geometry takes the `unchanged`
path: no version bump, no `needs_backfill` flip, no rows created, which makes the run safe on a
live stack and measures exactly R18's idempotent high-volume re-push. Verified before/after:
farm count, geometry_version, and analysis row count unchanged.

```
python -m services.loadtest --url /ingest/farm --method POST \
    --json-file ingest_replay.json --slo-set ingest --total 200 --concurrency 10
```

**Backfill enqueue**: the collect trigger needs `run_analysis`, so mint a local analyst JWT
(HS256 with the .env `RS_JWT_SECRET`; claims `{"sub": "loadtest", "roles": ["analyst"], "exp":
now+3600}`, plus `aud` if `RS_JWT_AUDIENCE` is set). Stop the consumers first so every call is
a pure enqueue and nothing reaches CDSE; purge afterwards:

```
docker compose stop worker beat
python -m services.loadtest --url /fields/{field_id}/collect --method POST \
    --header "Authorization: Bearer <token>" --slo-set backfill --total 200 --concurrency 10
docker compose exec redis redis-cli LLEN celery   # = total issued, proves nothing ran
docker compose exec redis redis-cli DEL celery
docker compose start worker beat
```

**Per-field analysis time and pipeline throughput**: mined from the 858 passes of real CDSE
history instead of an HTTP run, because every live trigger costs real CDSE quota and the
worker consumes it immediately. Per-pass write times (`min(created_at)` per field+scene),
segmented into contiguous runs at 30-minute gaps:

```
WITH passes AS (
  SELECT field_id, scene_id, min(created_at) AS t FROM analysis GROUP BY 1, 2
), gaps AS (
  SELECT field_id, t, CASE WHEN lag(t) OVER w IS NULL
         OR t - lag(t) OVER w > interval '30 minutes' THEN 1 ELSE 0 END AS new_run
  FROM passes WINDOW w AS (PARTITION BY field_id ORDER BY t)
), seg AS (
  SELECT field_id, t, sum(new_run) OVER (PARTITION BY field_id ORDER BY t) AS run_id FROM gaps
)
SELECT field_id, run_id, count(*) AS passes,
       round((extract(epoch FROM max(t) - min(t)) / 60.0)::numeric, 1) AS run_min
FROM seg GROUP BY 1, 2 ORDER BY 1, 2;
```

Results: full ~100-pass (18-month) field backfills completed in 12-57 minutes; sustained rates
1.7-10.2 passes/min. The worst sustained rate is 35 s/pass effective (with pipelining overlap,
so single-pass service time is bounded near it). A forward-fill pass costs ~10 governed CDSE
requests; at the confirmed 4 rps quota (S4.5) that adds ~2.5 s of bucket wait. p95 <= 60 s
covers the single-pass tail with CDSE variance on top. Note the history predates quota
governance going live; at ~10 requests/pass the 4 rps budget caps the pipeline near 24
passes/min, above every sustained rate measured, so the cap does not bind at current worker
concurrency.

Caveat: inter-arrival deltas understate concurrent service time, which is why the run-level
segmentation (not the raw p50 of 0.16 s between pass writes) is the basis. The `analysis` SLO
set stays HTTP-runnable for a staging soak where quota spend is budgeted.

## Harness changes in this slice

`--header "Name: value"` (repeatable, for the authenticated collect route) and `--json-file`
(POST body) on the CLI; a fourth SLO set `ingest`; the body is read before the event loop
starts so operations stay I/O-clean (ASYNC240). `parse_headers` is unit-tested; the wiring was
exercised by the real runs above.
