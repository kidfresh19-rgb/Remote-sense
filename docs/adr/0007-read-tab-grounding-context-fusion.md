# ADR 0007 — Read Tab Grounding Context Fusion & Telemetry Persistence

- Status: accepted
- Date: 2026-06-10
- Phase: Tier 2 of the improvement plan (moat analytics) / L4b Interpretation
- Builds on: ADR 0004 (weather port), ADR 0005 (activity correlation)

## Context

The plain-language narrative generated by the Claude API (Phase 4b) must explain vegetation index trends in a crop- and region-aware context. To do so, the model needs to evaluate index trends (e.g. canopy vigour/NDVI, nitrogen/NDRE, moisture/NDMI) relative to:
1. Preceding 14-day weather metrics (GDD accumulation and total precipitation).
2. Preceding 30-day activity logs (planting, fertilisation, spray, irrigation).

For auditability and Invariant 5 (provenance/reproducibility on every analysis), the agronomist must be able to verify the exact telemetry Claude reasoned from when drafting a narrative. Additionally, querying external APIs (weather and activity logs) on-demand during workspace UI rendering introduces severe latency and dependency concerns. 

We need to persist the grounding context snapshot directly alongside the draft narrative while strictly maintaining split-ownership (Invariant 6: remote-sense never writes or owns the master farm identity, geometry, or live activity feeds).

## Decision

We have implemented the following system components:

1. **Grounded Data Aggregator**: Created an async `aggregate_grounding_data` helper in `rs_interpret/grounding.py` that reads the target pass's `Analysis` row, queries weather metrics via `WeatherPort` (preceding 14 days), and queries agricultural interventions via `ActivityLogPort` (preceding 30 days).
2. **Schema & Model Expansion**: Enriched the `Evidence` dataclass and expanded the `Interpretation` SQLAlchemy model in `packages/rs_core/models.py` with three new columns:
   - `gdd_accumulation: float` (preceding 14d GDD)
   - `total_precipitation: float` (preceding 14d rainfall in mm)
   - `recent_activities: JSONB` (list of preceding 30d farm interventions: date, activity type, detail)
3. **Telemetry Persistence**: Modified the worker task (`interpret_field_pass`) to run the aggregator before calling the Claude API. The fetched context is injected into the user prompt, and persisted in the `interpretation` table alongside the generated draft narrative.
4. **BFF Endpoint & UI Integration**:
   - Updated the BFF response model `InterpretationOut` to return the grounding context.
   - Updated the Read tab panel header (`InterpretationPanel.tsx`) to display key grounding numbers (GDD, rain, events) in a header card.
   - Updated the index time-series chart (`IndexTimeseriesChart.tsx`) to overlay cumulative rainfall (bars), GDD (dashed line), and AgriTrack activity markers (vertical lines with type labels) directly on the SVG timeline.
5. **Prompt Refinement & Versioning**: Updated `SYSTEM_CONTEXT` in `prompts.py` to guide Claude on evaluating indices relative to water deficit, GDD anomalies, and fertilizer response. Bumped `PROMPT_VERSION` to `interp/v2`.

This solution respects split-ownership (Invariant 6): we only persist a read-only *snapshot* of the activities inside the remote-sense database for provenance, while AgriTrack remains the sole owner and system-of-record for live activities.

## Consequences

- **Verifiable Audit Trail (Invariant 5)**: Every agronomist review card is accompanied by the exact GDD, rainfall, and activities present on the pass date when the narrative was drafted, even if weather history is updated later.
- **Maximum Performance**: The workspace frontend loads GDD, rainfall, and activity overlays instantly from the database-backed BFF response, with no runtime round-trips to external weather/activity APIs.
- **Improved AI Quality**: Refined system context and telemetry inputs enable Claude to diagnose response interventions (e.g. "vigour rose following fertilizer application" or "moisture dropped despite irrigation").
